# 货车 v3 准确率协议

版本：`3.0.1`  
冻结日期：2026-10-22  
状态：开发/盲测评测契约；尚未取得完整身份 gold

## 1. 两个主指标

只保留两个顶层准确率指标。分项数据用于解释错误，不能通过求平均掩盖失败。

### 1.1 数量全对率

每个完整应评时刻必须同时满足：

- 南机位车辆数量正确；
- 北机位车辆数量正确；
- 南北重合车辆数量正确。

```text
数量全对_i = [south_pred = south_gold]
             AND [north_pred = north_gold]
             AND [overlap_pred = overlap_gold]

数量全对率 = Σ 数量全对_i / 完整数量真值时刻数
```

唯一数由公式推导：

```text
unique = north + south - overlap
```

模型若同时输出唯一数，必须等于该公式；否则该时刻数量判错或无效。唯一数不单独作为第三个业务指标。

南、北、重合三项各自的准确率，以及三项准确率的算术平均，仅作诊断：

```text
分项平均准确率 =
  (南机位数量准确率 + 北机位数量准确率 + 重合数量准确率) / 3
```

该平均分不能用于发布放行。

### 1.2 重叠车辆身份全对率

每个完整应评时刻必须同时满足：

1. 同一画面内所有真实互相重叠的车辆都被分别识别，预测的重叠关系边集合与真值完全一致；
2. 南北画面中同一物理车辆的 pair 集合与真值完全一致；
3. 没有把不同车辆错误合并，也没有让同一辆车重复配对；
4. 预测车辆与真值车辆能完整一对一关联，没有漏车、多车或重复实例。

```text
身份全对_i = 完整一对一台集
             AND predicted_overlap_edges == gold_overlap_edges
             AND predicted_cross_camera_pairs == gold_cross_camera_pairs

重叠车辆身份全对率 = Σ 身份全对_i / 完整身份真值时刻数
```

同画面重叠边和南北同车 pair 的 Precision、Recall、F1 与错误合并率仅用于定位错误来源，不能替代集合完全一致。

### 1.3 整时刻全对

```text
整时刻全对_i = 数量全对_i AND 身份全对_i
整时刻全对率 = Σ 整时刻全对_i / 同时具有完整数量与身份真值的时刻数
```

这不是第三个独立准确率维度，而是两个主指标的逻辑与。

## 2. 固定分母与拒答

- 分母取协议冻结时指定的全部应评时刻，不能因为失败、缺输出或拒答而删除样本。
- `review`、`abstain`、`invalid`、缺失输出均不计自动成功。
- 机位级 `status` 不是 `ok` 时，该时刻数量维度也不能自动成功。
- 数量真值未填（`truth_complete.quantity=false`，`quantities` 为 `null`）时只从数量分母排除，不得抛错，也不得影响身份维度。
- 可另行报告原始预测是否碰巧正确，但不能计入自动验收。
- 数量真值不完整的时刻只从数量分母排除；身份真值不完整的时刻只从身份分母排除。
- `unknown` 不得被视为正确。盲测验收要求相关真值完整。
- 每个指标必须同时输出分子、分母和比例；分母为零时比例写 `null`。

## 3. 位置与定位的使用边界

位置只用于把预测实例和真值实例建立一对一关系。默认使用归一化 bbox 的 IoU，阈值为 `0.5`。

本协议不把以下指标作为业务验收门槛：

- AP50、AP50:95；
- 定位 Precision/Recall/F1；
- IDF1、HOTA、ID Switch；
- 平均 IoU。

若真值中的车辆集合完整但实例无法一对一关联，该时刻身份全对记为失败。

## 4. 面积与大小

当前没有可信的人工面积、真实尺寸或统一尺度标签。近大远小也不能由二维画面面积直接还原真实大小，因此：

- 不计算面积准确率；
- 不训练或调参“大/中/小”分类；
- 只能做视觉合理性、相对大小和视频连续性的定性诊断；
- 未来如要量化，必须另建有人工确认的尺度或相对大小 gold，且不能与车辆身份标签混用。

## 5. 匹配与并列规则

- 同一时刻、同一机位内，预测车辆与真值车辆做一对一最大总 IoU 分配。
- 只接受 IoU 不低于 `0.5` 的匹配。
- 并列时按车辆 ID 字典序确定，保证重放结果一致。
- 重复 ID、重复关系边、同一对象多配、跨错机位 pair 均视为结构错误。
- 位置不是业务得分，只用于关联实例。

### 5.1 数量维度的结构有效性

三项整数与真值相同还不够，数量维度同时要求输出结构自洽：

- 两个机位都必须存在且 `status == "ok"`；
- 若某机位声明 `objects_complete=true`，则其车辆 id 必须唯一，且 `count` 必须等于车辆列表长度；
- 模型输出的 `unique` 必须等于 `south + north - overlap`。

协调裁定：`objects_complete=false` 只说明对象框不完整，**不直接否决数量维度**；它会让身份维度失败，因为身份维度要求完整对象集。这样可以区分“数对了但框错了”和“数错了”。

### 5.2 归一化框与真值时刻

- `bbox` 统一为 `[x, y, width, height]`（左上角 + 宽高），四项都在 `[0,1]`，且 `x+width ≤ 1`、`y+height ≤ 1`。
- 只吸收 IEEE-754 表示误差（1e-9），可见越界一律判无效。
- gold 中 `time_s` 必须唯一且为有限数；同一时刻不得用两个 `moment_id` 重复计入分母。

## 6. 重叠与跨镜定义

### 同画面重叠边

若同一画面中两辆车在顶面或可见外廓上发生遮挡、相互覆盖，或不能在不破坏任一车辆边界的前提下完全分开，则在两者之间记录一条无向边。

### 南北同车 pair

若北机位与南机位的两个车辆观察对应同一辆物理车辆，则记录一条 `(south_id, north_id)` pair。每个车辆观察在一个时刻最多参与一个跨镜 pair。

### 车辆口径

- 牵引车与其所连挂车计一辆物理车辆。
- 明确独立且可辨的货厢单独计。
- 叉车、轿车、面包车、行人、货堆和设备不计为货车。
- 无法确认的组成或身份保留 `unknown`，不得用历史数量补齐。

## 7. 开发集、回归集与盲测集

- 新 30 张是开发/回归素材，不是泛化证明。
- 正式盲测集按采集时段、物理机位、交通状态和重叠密度分层，且不得用于提示词、阈值或模型选择。
- 调参看过的样本自动转为开发集，不能继续计入盲测。
- 达到 100% 只能表述为“指定冻结盲测集全部维度正确”，不能表述为对任意未来场景的绝对保证。
- 零错误有限样本的单侧 95% 失败率上界为 `1 - 0.05^(1/n)`；样本量必须在报告中公开。

## 8. 性能报告

准确率达到门槛后，才比较性能。性能必须固定：

- 硬件和软件版本；
- 并发数；
- 像素预算和输入预处理；
- 调用次数、重试次数和运行次数。

至少报告端到端 p50/p95、吞吐、每帧请求数、tokens 和实际账单金额。人工复核次数、时长和成本必须单列，不能算自动正确。
