## 1. 一句话结论

**A′（紧贴纵向窗口 + 迭代语义去重）在五帧诊断上是 4/5，但 20 帧回归只有
13/20，差于纯 aisle 基线的 16/20。因此 A′ 不进入实现，也不继续调 prompt；
保留它的 far 窗口作为远端取证工具。生产主路径继续使用纯 aisle 基线。**

B（递归树）和 D（整帧后置审稿）淘汰为独立架构；C（场景图）只保留
`part_of` / `queue_index` 关系思路。

## 2. 评测口径

主真值：`accuracy/reviewed/user-final-review-v2-2026-10-21.json`

- 用户复核的 10 个时刻 × 南/北两个机位，共 20 个样本；
- 只有每机位总车数，没有人工大/中/小型拆分；
- 因此主表只评**总数** exact / MAE / 漏计 / 多计；
- 20 帧都在开发过程中使用过，是**开发集回归**，不是独立测试集；
- 样本缺失、调用失败单列，固定分母为 20；MAE 对有有效预测的样本计算并标注 valid_N。

历史 15/19 是缺一条成功响应时的结果，17/20 来自混合视图覆盖，均不作为基线。
用户红框支持现有数量；旧的“南侧 5 合并为 3”推断已撤回。

## 5. 成本

A′ 20 帧：186 次调用、186 张输入图、511,742 token、累计 wall 1,814.4 s、
均值 90.7 s/帧、p95 142.7 s；0 次调用失败。

相对整帧基线（20 次调用、72,365 token、均值 17.2 s/帧）：约 9.3 倍调用、
7.1 倍 token、5.3 倍 wall。成本是真实的，但没有换来准确率。

## 6. 五条机制

| 路线 | 核心机制 | 结论 |
|---|---|---|
| A 透视条带 | 按 `far/upper/mid/near` 四条横向带切图，core 不重叠 | 降级为候选/取证生成器 |
| **A′ 紧贴窗口** | `far_b` 紧贴货厢行 + `mid/near/bottom` 跟随通道；跨窗语义去重 | 回归失败，仅保留 far 取证 |
| B 递归树 | 模型提区域 → 递归放大 → 父候选在子 core 内被 supersede | 淘汰 |
| C 场景图 | 一次整帧输出 lanes + 每车 `lane_id/queue_index/part_of` | 仅保留关系思路 |
| D 后置审稿 | 首轮框画回图，再让模型独立重数并找漏/重/车型错 | 淘汰 |

共享去重闭环：几何只提出候选对；每一对都由多模态模型判断
`same_vehicle`；合并后重算存活候选，最多 3 轮；跨窗上下相邻框也会被提出，
但仍由模型判定。显式 `is_truck=false` 的候选无论置信度都拒绝，低置信负例
保留在 `rejected` 并标 `needs_review`。

## 7. 失败案例

完整错误表、逐帧机制、B/C/D 的失败向量见 `failures.md`。

`south_600` 的车头/挂车拆分仍未解决；`north_900`/`south_900` 则展示了相反
方向的错误——把两节不同货厢合成一辆。调阈值或加一句 prompt 只能把错误从
一类推到另一类，不能稳定同时修复。

## 8. 路线判定

- **生产主路径**：纯 aisle 单裁剪基线（16/20、MAE 0.25）。
- **A′**：不进入实现；`far_b` 裁剪仅作为远端两节货厢的复核证据。
- **A**：候选/取证生成器，不输出自动总数。
- **B / D**：淘汰为独立架构。
- **C**：只保留 `part_of` / `queue_index`；不单独计数，需在新的关系真值上验收。
- **不再做**：同一机制的 vN prompt 调参、用五帧分数宣称能力。

## 10. 边界

- 这是开发集回归，不是独立新时段泛化验证；
- 只有 Doubao 端点稳定可用，不是多模型共识；
- 人工 v2 只有总数，不声称车型准确率；
- 未完成跨机位唯一实体；
- A′ 只跑了一次 20 帧，随机性影响未测；
- 不声称五帧 4/5 等于 80% 生产准确率。
