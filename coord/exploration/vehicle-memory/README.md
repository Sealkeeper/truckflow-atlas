# 车辆身份记忆路线：最小机制与实测边界

更新时间：2026-10-21（北京时间）。分支：`research/vehicle-passport`，冻结调用提交：`0341a8c92acc3bb745a0c25af9095a5672efea48`。

## 当前结论

- 记忆库不是自动计数主线。当前干净基线是 **16/20 count exact、MAE 0.25**；身份字段没有完整人工真值，`cargo_id`、`tractor_id`、`vehicle_session_id` 指标均为 **未测**。
- 跨机位自动放行仍是 **no-go**：0/10 自动放行、10/10 复核。零自动错误来自零覆盖。
- 本轮已执行的 20 次双尺度调用是**无记忆的同帧输入消融**，不是记忆库收益。结果为 **14/20 exact、MAE 0.35**，修复 1 帧、回归 3 帧、漏 4、多 2，当前形式淘汰。
- 组件装配实验在调用前冻结，但按中枢“已开始实验保留、不再追加付费调用”的要求 **未运行**；没有 8 帧分数，也不得引用任何预期结果。
- 此前 L2 的 2 次补检是旧机制成本；本轮实际新增模型请求只有双尺度 20 次。

## 模型实际看到了什么

双尺度调用只包含以下两项视觉输入：

| 输入 | 来源时间 | 实际内容 | 是否包含历史候选 |
|---|---|---|---|
| 图 1 全局 aisle | 当前样本的同一视频时刻 `t` | 归档的当前帧全局裁剪 | 否 |
| 图 2 固定远区 | 同一帧 `t`，由图 1 确定性生成 | 图 1 宽度 100%、高度 `0..0.52` 的未缩放裁剪 | 否 |

提示词没有输入：

- 前一帧、后一帧或未来观测；
- 另一机位画面；
- 人工红框、人工计数、人工答案；
- L1/L2/L3 历史记忆条目；
- 候选车辆集合、箱号、车牌或历史预测。

模型返回的车辆、逐字文字和视图标记是**本次响应**产生的证据，不是调用前注入的记忆。真值只在响应冻结后由评测脚本读取。

### 历史记忆的来源时间

`generated/memory_cache.json` 是离线证据索引，没有进入上述双尺度请求：

| 层 | 条目 | 观测时间 | 用途 |
|---|---:|---|---|
| L1 | 66 | 当前归档中的 10 个时刻之一 | 观测级护照 facet，TTL 300 秒 |
| L2 | 2 | `north_5` 在 t=5；`north_600` 在 t=600 | 旧定点补检探针，TTL 30 天 |
| L3 | 4 | t=5、300、600、2100 的计数失败 | 回归样本，TTL 90 天 |

每条记忆都有来源、观测/创建时间、版本、TTL、过期时间、状态、冲突和 `supersedes`。

## 身份单位

| 字段 | 只标识 | 当前值状态 | 禁止事项 |
|---|---|---|---|
| `cargo_id` | 货厢/箱号 | 未验证 | 不能用箱号建立永久整车 ID |
| `tractor_id` | 牵引车/车头/车牌 | 未验证 | 不能证明未观察到的换挂历史 |
| `vehicle_session_id` | 一次有当前挂接或连续性证据的整车会话 | 单帧 `provisional` | 换挂、OCR 不清、仅箱号相同均不得延续 |

模型逐字文字只保留在 `readable_text.verbatim/tokens`。未分类文字不会同时进入 cargo 和 tractor 候选层。没有完整人工 ID 真值，schema、缓存和分层本身不是身份准确率。

## 与并行输入尺度路线的差异

两条路线同属“当前帧全局 + 固定细节”机制族，**不能当成两个独立假设或两份独立样本**。

| 项目 | 本路线 `dualscale_v1` | 公共 `input-representation` 预注册 v1 |
|---|---|---|
| 定位 | 无记忆消融，检查记忆路线是否存在纯输入尺度混杂 | 输入尺度与空间表示主路线 |
| 细节来源 | 归档 aisle 图的高度 `0..0.52` 全宽裁剪 | 原帧中心远区 source rect，Lanczos 2x |
| 细节尺寸 | 1040x998，与全局同像素密度 | 560x1120，局部放大 |
| 图像顺序 | 全局、细节、提示词 | 全局、细节、提示词 |
| 输出 schema | `evidence_views`、专用字段较简 | 原帧坐标、`seen_in`，更严格几何/字段校验 |
| 传输重试 | 0 次，失败保留 | 仅限定传输错误最多 3 次 attempt |
| 并发 | 2 | 1 |
| 本轮结果 | 14/20 exact，MAE 0.35 | 以该路线自己的 manifest 与报告为准 |

因此，本路线的 14/20 不能用来评价并行尺度路线，也不能说“记忆降低了准确率”；它只说明把固定远区裁剪加进当前提示词并没有修复既有漏计，并引入了新的回归。

## 已测与未测

已测：

- 20 帧机位计数 exact、MAE、漏计和多计；
- 相对 16/20 基线的修复与回归；
- `counts.total == len(vehicles)` 一致性；
- 请求成功数、失败数、token 和延迟；
- 缓存/schema 的结构校验。

未测：

- `cargo_id`、`tractor_id`、`vehicle_session_id` 身份准确率；
- 逐车框、车型、跨帧身份和跨机位身份；
- 模型自述“只计一次”是否与真实视觉静止对应；
- 复核耗时、复核精度、生产并发和供应商失败率；
- 独立新时段泛化。

双尺度 20 个响应都满足 `counts.total == len(vehicles)`，没有视图分项相加字段；但模型自报去重不等于视觉证明。该实验仍有 2 个过计样本，不宣称双视图零重复。
