# 公开发布检查清单

逐项打勾才能公开。任何一项打不了勾，就先做私有协作。

## A. 法律与授权

- [ ] 监控画面的**使用权**明确：是谁的场地？合同里是否允许对外展示？（这条只有你能回答）
- [ ] 选定 LICENSE（建议：代码 MIT / Apache-2.0；数据不授权）
- [ ] 确认项目名、描述、作者署名方式

## B. 素材隔离

- [ ] `assets/frames/**`（62 张真实帧）不进公开仓
- [ ] `review/**` 截图不进公开仓
- [ ] `accuracy/reviewed/**`（客户真值）不进公开仓
- [ ] `coord/**/crops/**`、`**/figures/**` 里的裁剪图逐张过一遍
- [ ] 用 `git log --all --stat` 确认历史里没有素材；如有，**新建干净仓**而不是转公开

## C. 代码卫生

- [ ] 全部 `D:\File\PROJECT\...` 绝对路径改成相对路径或环境变量
- [ ] `.env` / 密钥扫描：`gitleaks detect --no-git`
- [ ] 公开仓体积 < 20 MiB
- [ ] `python -m pytest -q` 与 `run_audit.py` 全绿
- [ ] README 里的命令**在干净克隆上**能跑通

## D. 协作设施

- [ ] `CONTRIBUTING.md` 置顶，硬规则（禁检测器 / 禁素材 / 带分母）写在最前
- [ ] 3 个 issue 模板：任务认领、指标歧义、评测漏洞
- [ ] PR 模板：要求填分子分母、失败条件、复现命令
- [ ] CI：跑单测 + 红队 + 密钥扫描（不含任何真实数据）
- [ ] `CODE_OF_CONDUCT.md`（可选，但公开仓建议有）

## E. 盲评通道（Tier C）

- [ ] 私有 runner 或自建评测服务可用
- [ ] 提交格式固定（predictions JSON schema）
- [ ] 只回传分数，不回传图像与真值
- [ ] 排行榜口径写死：数量全对率与身份全对率**分别**公布，不合成一个总分

## F. 公开后的第一周

- [ ] 发 3–5 个标注清楚的 `good first issue`（评测漏洞、文档、可视化类）
- [ ] 准备一份"常见误解"文档，尤其是为什么不用检测器
- [ ] 明确回应时效：外部 PR 谁来审、多久回
