# 准确率协议

> 本文是早期产品设计草案，不是当前评分或部署约束的权威协议。
> 当前业务验收采用 [评测协议 v3](../coord/evaluation-v3/PROTOCOL.md) 的数量全对率与重叠车辆身份全对率，
> 不以本文的车型、曲线或负载率诊断替代两项主指标，也不因模型拒答而缩小应评分母。
> “模型一致”不证明实际正确，正式分数仍须独立人工真值。
> 实时检测器依赖与离线教师的最新边界见 [贡献指南](../CONTRIBUTING.md#四条硬规则)。
> 下文保留作产品设计背景，未实现模块与早期流程建议不能当成已经验证的结果。

## 1. 唯一验收目标

项目目标是：在已标注基准集上，每个验收时刻的“总车数、分车型数量、跨机位唯一车辆集合”与金标准完全一致，零漏计、零重计、零车型错误。

这是一个严格目标，不等于对外宣称任意新视频都能盲测 100%。系统必须区分：

- **确定结果**：多模型一致、裁剪复核通过、跨机位与时间连续性检查通过。
- **待复核结果**：存在遮挡、边界、车型或去重分歧。
- **拒答**：画面质量不足以支持判断。

只有在基准集上实测并留痕的结果，才能写入准确率报告。

## 2. 金标准制作

1. 分层抽样：覆盖开场、高峰、低谷、换班、夜间、遮挡、跨机位同时出现等场景。
2. 每个样本由两名独立标注者分别给出逐车框、车型、机位和跨机位匹配。
3. 两人不一致处由第三人裁决；仍无法判断则标为 `indeterminate`，不进入“确定计数”分母。
4. 每条标签保存原帧、裁剪、标注者、时间、版本与变更理由。
5. 开发集与验收集分离；调提示词和融合规则只能看开发集。

## 3. 指标

### 帧级

- Exact Match：总车数和分车型数量全部正确。
- Count MAE：总车数绝对误差。
- Type Macro-F1：大/中/小三类。
- Miss / Extra：漏计与多计。
- Duplicate Rate：跨机位与相邻时间重复计数。
- Review Precision：进入复核的样本中真正不确定的比例。

### 时间序列

- 采样时刻计数曲线与金标准曲线的 MAE、峰值误差、峰值时间偏差。
- 车辆首次出现/最后消失事件的精确率与召回率。
- 唯一编号的 ID switch 与碎片化次数。

### 负载率

- 数量误差传导后的负载率误差；
- 容量参数敏感性区间，不能只报一个点估计。

## 4. 识别流水线

1. **确定性抽帧**：FFmpeg 按场景自适应抽帧 + 固定安全采样；记录精确帧号。
2. **画面准备**：通道区域裁剪、重叠分块、轻度放大；不做目标检测或跟踪。
3. **多模型独立识别**：每个模型基于相同证据输出逐车 JSON，包括框、车型、可见性、理由。
4. **裁剪复核**：把每辆候选车放大裁出，由另一轮模型判定“是否货车、车型、是否同一辆”。
5. **共识**：按框与外观语义合并；票数不足或矛盾则进入复核。
6. **时序关联**：仅使用模型给出的外观语义与位置描述关联相邻时刻，禁止传统视觉跟踪器。
7. **跨机位合并**：模型对两机位候选做配对，输出匹配理由与置信度。
8. **人工门禁**：所有不确定项复核后才可生成“已核验”报告。

## 5. 防作弊与防漂移

- 不根据上一帧数量直接填当前帧；每个值必须有当前帧证据。
- 不把抽样帧的 4/5/7 辆平滑成“看起来合理”的曲线。
- 随机盲测时隐藏模型票数和历史计数，避免锚定。
- 每次提示词、模型、采样策略变更都跑固定回归集。
- 记录模型版本、参数、耗时、token 与失败重试。
