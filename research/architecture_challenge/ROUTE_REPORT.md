## 5. 为什么 A′ 胜出

### 5.1 它修的是取景，不是加一句“不要漏计”

`north_600` 的两节货厢在整帧里与展台、立柱和队列连成一片；紧贴货厢行的窗口把它们
变成两个有明确边界的箱体。先前 smoke 还显示，宽 `row_a` 裁剪会产生 3–5 个候选，
包括展台和阴影；收紧到 `x=0.39–0.57, y=0.14–0.42` 后两个重复样本都给出灰/蓝两节。

### 5.2 它需要一个“合并闭环”

仅靠一次 pair 排序会漏掉 `mid + near + bottom` 的第三个碎片。新的
`fusion.dedupe_candidates` 在合并后重算存活候选，并对不同窗口的上下相邻框继续
提出 A/B 语义判定。`north_300` 从 4 到 3、`south_1200` 从 6 到 5 都来自这个闭环。

### 5.3 它的代价是真实的

约 10 次调用、28.7k token、109 s/帧；基线约 1 次调用、3.6k token、16 s/帧。
远端恢复不是免费的。20 帧回归若不能把 exact 从基线的 16/20 提高到至少 17/20，
就不值得把成本翻几倍。

## 6. 其他路线的判定

### A 透视深度条带

保留为候选生成器：它证明了“按透视深度分段”能让远端进入视野，但 2/5 exact、
多 2，说明宽条带和 core 边界仍然过粗。若 A′ 的 far 窗口在 20 帧中不稳定，
可以把它作为第二取证视角，而不是主计数。

### B 递归区域树

淘汰当前形态。91 次调用、291k token、1,167 s，只有 1/5 exact、多 4；
每帧都打满 8 个节点，成本和调试复杂度均不划算。未来只有在固定根区域、
节点数 ≤ 4 并有明确父子归属证据时才重新评估。

### C 场景图

不单独计数，保留 `part_of` / `queue_index` 关系。它便宜（21 次调用、67k token），
但连续漏远端队列（漏 4），不适合作为主计数。最有价值的下一步是把它用于
`south_600` 的车头/挂车关系，而不是要求它自己找全所有车。

### D 整帧后置审稿

独立形态淘汰。它的五帧总数与基线完全相同，说明“再问一遍整帧”没有提供新信息；
成本 27 次调用、94k token。可以作为 A′ 之后的“只删不加”审稿门，但不能作为
主架构。

- Count MAE 0.300；
- 累计漏 5、多 1；
- 错误集中在 `north_5`（-2）、`north_300`（-1）、`north_600`（-2）、

## 8. 复现

在 `research/architecture_challenge` 目录执行：

```powershell
python src/arch_windows.py --frames north_300,north_600,south_600,north_1200,south_1200 --force
python src/evaluate_architectures.py
python src/render_evidence.py --architectures bands,windows,tree,scene_graph,critic
```

模型配置从仓库根 `.env` 读取，API Key 不入库。每次运行保留：

- `runs/<architecture>/<camera>_<time>.json`：完整 prompt、原始回答、reasoning、
  usage、失败与候选；
- `evidence/<architecture>/<camera>_<time>/`：窗口裁剪、A/B 证据、车型裁剪、
  最终框标注。

完整证据目录约 95 MB、345 张图，仓库只提交关键证据图以控制 PR 体积；
其余图像可用上面的命令从原帧和 `runs/` 重新生成。

## 9. 局限与待验证

1. **单一模型**：本轮只有 Doubao 端点稳定可用。智谱图像请求返回 400
   （`messages.content.type` 只接受 text）；AIBox 的 `glm-5.3`/`glm-5.2`
   不稳定或代理超时。不能把这组结论外推成多模型共识结果。
2. **随机性**：同一 far 裁剪重复调用曾出现 1/2/3 个候选；树根调用曾单次耗时
   4,043 s，后来才加入 150 s 流式 deadline。单次运行不能证明稳定。
3. **五帧不是回归集**：A′ 的 4/5 只是在诊断帧上的结果，20 帧尚未跑；
   不能宣称 80% 生产准确率。
4. **无人工车型**：v2 只提供总数；v0 的大/中/小标签仍是初标。
5. **边界口径**：`south_600` 的车头/挂车合并、`south_1200` 的底部货厢归属
   仍需要人工口径确认；不要为了 exact 过拟合。
6. **无跨机位唯一实体**：本报告只评单机位逐帧总数，没有完成跨机位去重。

## 10. 决策门

### 进入实现前必须满足

- A′ 在人工 v2 的 20 帧上至少 17/20 总数 exact；
- MAE ≤ 0.25，且不出现比基线更大的系统性多计；
- `south_600` 的 +1 被关系层消除，而不是靠调提示词偶然压掉；
- 至少重复 2 次运行，失败/超时记录完整；
- 平均 wall 在本机 ≤ 90 s/帧，或给出可接受的批处理吞吐方案。

### 若不满足

保留整帧基线作为生产主路径，把 A′ 的 far 窗口作为“远端复核证据生成器”；
不合并 A′、B、C、D 的任何自动总数到主流水线。
