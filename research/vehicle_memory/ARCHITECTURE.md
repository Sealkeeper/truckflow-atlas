# 车辆护照与三层记忆架构

状态：研究原型，可重放；不是生产验收结果，也没有自动计数放行能力。

本设计回答一个问题：车辆记忆能否在可审计的来源、版本和过期规则下减少漏计、跨机位重复和人工复核成本；同时探索当前帧输入表示和组件装配约束能否直接改善识别。准确率优先，性能第二。

原型当前冻结的“1 次主调用 + 最多 1 次 L2 定点补检”只是历史可重放配置，用于比较既有证据，**不是产品调用上限**，也不能为了省调用而隐藏错误或牺牲识别准确率。本轮冻结过 28 次实验预算（20 次双尺度 + 8 次组件装配）；实际执行双尺度 20 次，组件装配按中枢“不再追加付费调用”要求保持未运行。预算本身不是生产约束。

当前结论是：

- L1 车辆护照和 L3 失败记忆有条件值得做，主要用于证据留存、复核路由、跨机位去重门禁和回归测试。
- L2 场景记忆能指出“哪里可能漏”，但实测补检同时出现一个修复和一个回归，不能自动上线。
- 记忆库不能解决第一次看见一辆车时的漏计；它只能保存“以前在这里漏过”和提供该区域的局部补检先验。
- 当前没有经过验证的跨机位硬身份，自动跨机位匹配为 no-go。

## 1. 约束和边界

身份判断只使用多模态模型返回的语义护照特征：车顶/货厢/车头颜色、纹理、车型、尺寸等级、逐字可读文字。

以下信息不用于决定跨机位身份：

- 传统目标检测、分割、IoU 跟踪、光流和传统视觉分类器；
- 跨机位 bbox 的 IoU、中心点距离或透视映射；
- 仅凭时间相邻推断“还是同一辆车”；
- 仅凭颜色种类或车辆数量相同进行配对。

bbox 仍有三项合法用途：

1. 从当前帧生成可审计的车身裁剪；
2. 在同一帧的局部补检中记录裁剪坐标，帮助人工复核；
3. 保存历史观测位置，供漂移诊断和召回区域维护。

局部补检框映射回主画面后也不进入语义匹配分数。匹配器没有 `x`、`y`、`IoU` 或中心点特征。

## 2. 原型调用路径与实验预算

```text
历史重放配置（仅用于解释已有 16/20 基线）
相机帧
  └─ 1 次主多模态调用
       ├─ 返回当前帧车辆集合和语义护照 facet
       ├─ 建立或更新 provisional passport
       ├─ 跨机位语义匹配
       └─ 场景先验命中时，历史上曾最多追加 1 次局部补检
            ├─ 只列补检窗口内车辆/独立货厢
            ├─ 与主调用候选做同帧语义去重
            └─ 任何未消除的不确定性进入 review
```

禁止逐车重复调用模型是历史原型的边界，不是本轮实验的产品要求。主占用调用不能因为“记忆里以前有这辆车”而跳过，因为车辆可能已经离场；能省的只能是额外的跨机位配对验证调用，并且只有在存在经过验证的硬身份时才可计为真实节省。

本轮冻结两套互不相同的机制：

| 实验 | 机制 | 调用 | 目的 |
|---|---|---:|---|
| `dualscale_v1` | 一次调用同时输入当前全局图和同帧固定上半部细节图 | 20 | 检验远车细节是否提高召回，且不把两图相加 |
| `component_assembly_v1` | 显式输出 tractor、cargo 和 `assembly_status` | 8 | 检验组件装配约束是否减少车头/货厢误拆与独立货厢误合并 |

两套实验都不输入前后帧、其他机位、人工红框、人工计数或历史答案。失败保留在固定分母，不做静默重试。

## 3. L1：车辆护照

护照是一次车辆外观证据的结构化快照，不等同于已确认的物理车辆。当前 20 个相机帧生成 66 个观测级 `provisional` facet，没有任何 `confirmed` 身份。

完整导出结构见 `PASSPORT_SCHEMA.json`。护照不是整车 ID；身份拆成三个不可混用的层：

| 层 | 只代表 | 当前状态 | 合并规则 |
|---|---|---|---|
| `cargo_id` | 货厢/箱号 | 未验证 | 只标识货厢，不能建立整车会话 |
| `tractor_id` | 牵引车/车头/车牌 | 未验证 | 只标识车头，不能证明未观察到的换挂历史 |
| `vehicle_session_id` | 一次当前挂接或连续观测的整车会话 | `provisional` | 必须有当前挂接证据或连续性证据；换挂、OCR 不清或仅箱号相同均不得延续 |

核心字段包括：

| 字段 | 用途 |
|---|---|
| `passport_id` | 可追踪 ID，不等于车牌或物理实体 ID |
| `first_seen` / `last_seen` | 首次和末次观测时间、帧键 |
| `cameras` | 出现过的机位 |
| `bbox_history` | 当前帧观测框、可见性和来源 |
| `visual` | 车顶颜色/纹理、货厢颜色/类型、车头颜色 |
| `readable_text` | 逐字文本和 token；未验证文本不会被纠错或补全 |
| `identity_layers` | `cargo_id`、`tractor_id`、`vehicle_session_id` 三层硬性隔离 |
| `memory_metadata` | 来源、观测/创建时间、版本、TTL、过期时间、状态、冲突和 supersedes |
| `dimension_class` | `large / medium / small / unknown` |
| `evidence_crops` | 可复核的车身裁剪 |
| `confidence` | 观测级证据置信度，不是物理身份概率 |
| `status` | `confirmed / provisional / merged / split` |
| `provenance` | 原响应、模型、token、延迟和不确定标记 |
| `merge_history` | 合并/拆分审计记录 |

状态规则：

- `provisional`：只有当前观测，不能声称跨机位身份；
- `confirmed`：存在经过验证的硬身份，或满足人工确认的完整证据链；
- `merged`：两个以上护照被合并，必须保留来源 ID 和证据；
- `split`：原护照被拆分，必须保留拆分理由和证据。

当前模型输出的文字只是“逐字候选文字”，不是已验证 OCR。比如 `粤T62619`、`QL66002` 可以保留在 `readable_text.verbatim/tokens`，但在没有独立 OCR/箱号核验时不能进入 `cargo_id.value` 或 `tractor_id.value`，也不能作为自动合并依据。原始未分类文字同时写入两个候选层会造成语义串层，当前实现禁止这种做法。

### 3.1 记忆写入与过期

`generated/memory_cache.json` 当前包含 66 个 L1 观测、2 个 L2 场景探针和 4 个 L3 计数失败回归，字段由 `MEMORY_CACHE_SCHEMA.json` 约束。

| 层 | 当前 TTL | 过期后的用途 |
|---|---:|---|
| L1 观测护照 | 300 秒 | 不再作为新鲜身份证据；保留审计 |
| L2 场景易漏区域 | 30 天 | 不触发补检，需重新验证 |
| L3 失败回归 | 90 天 | 仍可作回归样本，但不能直接决定在线计数 |

每条记录必须保留 `source`、`observed_at_video_s`、`created_at_utc`、`version`、`ttl_s`、`expires_at_utc`、`state`、`conflicts` 和 `supersedes`。当前记录均为 `fresh`，尚无跨版本 supersedes 或冲突合并案例。

**身份字段未测**：本数据集没有完整的人工 `cargo_id`、`tractor_id` 和 `vehicle_session_id` 真值。因此三层 schema、缓存和 TTL 只能证明证据可管理，不能声称身份识别准确率提升。

## 4. 语义匹配公式

对于两个护照 facet，先计算各语义维度的 Jaccard 相似度：

```text
S = 0.32 * cargo_colour
  + 0.18 * roof_colour
  + 0.18 * body_type
  + 0.12 * texture
  + 0.10 * cab_colour
  + 0.10 * size
```

未观测到的维度得 0 分，不按 0.5 填补。组合权重的总分上限是 1.0。

硬身份优先规则：

- 两个护照都有已验证的同一箱号/车牌/可读文字时，分数提升至 0.98，可进入自动匹配；
- 文字逐字相同但尚未验证时，只进入 `review`；
- 两个都有文字但 token 不同时，记录 `readable_text_disagrees` 并压低分数；
- 车型角色、尺寸等发生明确冲突时，进入 `reject` 或 `review`。

决策阈值：

| 条件 | 决策 |
|---|---|
| 已验证硬 ID 完全相同 | `auto` |
| 跨机位 `S >= 0.82` 且至少两个语义类别一致、无冲突 | `auto` 候选 |
| 同一帧定点补检去重，`S >= 0.52` 且至少两个语义类别一致、无冲突 | `auto` 重复 |
| `0.52 <= S < 0.82`，或只有同色/弱证据 | `review` |
| 低于复核阈值且无共享身份特征，或明确冲突 | `reject` |

硬身份层和语义相似度必须分开处理。当前没有验证过的 hard ID，语义分数只用于复核路由。跨机位释放门禁比单次配对的 `auto` 更严格：

- 两个机位都有车辆时，必须有已验证的跨机位配对；
- 只要仍有未决候选，整组进入 `review`；
- 没有任何已验证配对时，整组进入 `review`；
- 任何合并都记录证据，不静默合并。

该门禁只决定“跨机位结果是否可自动释放”，不证明单机位计数一定正确。当前 10 个时刻全部进入复核，自动放行是零覆盖，不能把“自动放行错误为 0”当成准确率成就。

## 5. L2：场景记忆

L2 按机位和区域保存：

- 通道拓扑、可见边界和容量先验；
- 历史易漏区域及对应的局部裁剪配方；
- 该区域的历史召回、补检后新增数、重复识别数和回归结果；
- 最后一次验证时间和证据链接。

它解决的是“主画面中远处或边缘目标可能被漏掉”的召回问题。它不能证明车辆身份，也不能直接修改当前帧计数。

已做的两个定点实验只用于诊断：

| 样本 | 主调用 | 补检 | 合并后 | 真值 | 结果 |
|---|---:|---:|---:|---:|---|
| `north_600` | 2 | 3，识别 1 个重复 | 4 | 4 | 修复 |
| `north_5` | 4 | 4，重复识别失败 | 8 | 5 | 过计 |

两次补检共 2 次新调用、8,923 tokens、41.96 s；两个样本的相机计数 MAE 仍为 1.5。一个修复、一个回归，不能外推为稳定召回能力。本轮双尺度实验正是为了检验“同帧细节输入”能否取代这种补检后相加的机制。

## 6. L3：失败记忆和回归门禁

失败记忆应保存：

- 错误类型：漏计、过计、误合并、误拆分、车型漂移；
- 对应相机帧、主裁剪、局部裁剪、原响应和真值；
- 修复前后的计数与证据链接；
- 是否通过同一套回归门禁；
- 模型、提示词、阈值和时间戳。

当前已知模式包括 `north_5`、`north_300`、`north_600` 的漏计和 `south_2100` 的过计。归档的多模型共识结果只能作为 L3 回归证据：

| 规则 | 自动覆盖 | 自动正确 | 自动错误 | 复核率 |
|---|---:|---:|---:|---:|
| R1 三模型一致 | 13/20 | 11 | 2 | 35% |
| R3 任一异议或不确定即复核 | 12/20 | 11 | 1 | 40% |
| R5 四模型一致且不确定即复核 | 8/20 | 8 | 0 | 60% |

这些规则没有一个达到全样本自动放行；R5 的“自动部分 8/8 正确”不能改写成“全量 100%”。

## 7. 本轮新机制实验

`experiments/PREREGISTRATION.md` 和对应 `config.json`、`prompt.txt` 在模型调用前冻结。两套实验现在必须按实际执行分别解释：

| 实验 | 实际请求 | 结果 | 判定 |
|---|---:|---|---|
| `dualscale_v1` | 20 成功 / 0 失败 | 14/20 exact，MAE 0.35；漏 4、多 2；修复 1、回归 3 | 当前形式淘汰 |
| `component_assembly_v1` | 0 | 无分数 | 冻结未运行，不追加调用 |

双尺度只输入当前全局图与同一帧固定远区裁剪，不输入任何记忆条目、历史候选、前后帧、其他机位或人工答案。因此它是**无记忆的同帧输入消融**，不能写成记忆库收益。20 个响应均满足 `counts.total == len(vehicles)`，没有视图分项相加字段；但模型自报去重不等于真实视觉证明，且仍有 2 个过计样本，不能宣称双视图零重复。

双尺度的错误变化：

- 修复：`north_300` 从 2 到 3，真值 3；
- 回归：`south_900` 5 -> 4、`south_1500` 5 -> 4、`north_2600` 2 -> 3，真值分别为 5、5、2；
- 仍在错：`north_5` 4 -> 3（真值 5）、`north_600` 2 -> 3（真值 4）、`south_2100` 保持 4（真值 3）。

该机制与公共 `input-representation` 路线同属“全局 + 固定细节”，但细节框、尺度、输出 schema 和并发不同；它是无记忆消融，不是独立假设，也不能用其结果评价另一路线。`cargo_id`、`tractor_id`、`vehicle_session_id` 仍为**未测**。

本轮实际新增模型请求为 20，低于 40 次实验上限；此前 L2 的 2 次调用是旧机制成本，不能计入本轮新增调用。

## 8. 对四类问题的实际作用

| 问题 | L1 护照 | L2 场景记忆 | L3 失败记忆 |
|---|---|---|---|
| 第一次看见一辆车而漏计 | 无直接帮助 | 只提示可能漏的区域，仍需补检模型 | 只能把同类历史错误带回回归测试 |
| 跨机位重复 | 提供语义配对证据和复核门禁 | 可保存配对易错区域 | 记录误合并/漏合并案例 |
| 身份漂移 | 保存外观变化和证据历史 | 可提示区域视角差异 | 标记漂移模式并阻止自动合并 |
| 复核成本 | 硬 ID 命中可省一次配对验证调用 | 定点补检可减少全图重跑 | 用历史错误排序复核队列 |

首次漏计的核心仍是当前帧目标召回和局部补检质量。记忆库不能替代模型看见车辆，也不能替代当前帧证据。

## 9. 误合并的业务后果

把两辆真实车辆合并成一个护照会同时造成：

- 少计一辆，占用和容量被低估；
- 计费、调度或出场记录漏单；
- 两辆车的轨迹、箱号和维护历史串号；
- 后续复核被一个“看似已确认”的错误身份锚定。

反向的误拆分会导致多计和重复计费。因此当前策略宁可将证据不足的配对送入 `review`，也不静默合并。复核不是免费兜底：100% 复核率意味着当前自动化的运营收益为零，后续必须单独测量复核耗时和复核精度。

## 10. 时间连续性

本期没有把 `t-1/t/t+1` 的身份延续写进护照确认规则。既有实验显示三帧时序条没有修复远处漏计，反而在部分帧扩大错误自信。

未来时间连续性最多作为当前帧候选的变化提示或事件索引。任何跨时间延续仍必须绑定当前帧的独立可见证据，不能按上一帧数量或语义相似度自动填当前帧。

## 11. 当前限制

- 只有 10 个时刻、20 个相机帧、66 个观测；不是任意新视频的准确率。
- 用户真值已用于评估，但没有双人独立标注和第三人裁决的完整章程记录。
- 所有护照都是 `provisional`，没有已验证的硬 ID。
- `cargo_id`、`tractor_id`、`vehicle_session_id` 没有完整人工真值，三项身份指标均**未测**。
- 16 个配对探针是历史模型调用，只用于审计；语义匹配器在 8 个候选配对上仍没有自动 `yes`。
- L2 只有两个定点样本，补检后的语义去重既修复过，也造成过过计。
- 未测量人工复核时间、复核精度、生产并发和网络失败率。
- 未使用或声明任何 100% 准确率。

## 12. 下一步的准入条件

零调用可行性审计已完成，见 `OFFLINE_IDENTITY_FEASIBILITY.md` 和 `generated/offline_identity_audit.json`。现有数据有 0 个人工身份字段、0 个人工换挂事件、0 个 prior-only/future 切分，因此离线身份实验的 `ready=false`。10 项策略不变量通过只能证明系统没有把未验证文字升级成硬 ID，不能证明身份准确率。

1. 先采集并双人复核 `cargo_id`、`tractor_id`、`vehicle_session_id` 真值，以及同车头换货厢、同货厢换车头、OCR 不清和仅箱号相同的负例。
2. 按时间建立 prior-only 建库段与 future target 段；测试目标不得进入建库，不得使用人工框或答案。
3. 预注册 session link precision/recall、false merge、换挂延续错误和复核率后，再做离线实验。
4. 为箱号/车牌建立独立 OCR 或人工核验 provenance，验证通过后才允许 `confirmed` 状态和硬 ID 自动匹配。
5. 不在当前数据上重复“全局 + 固定远区”付费调用；L2 补检只有在 20 帧回归同时改善漏计、过计和去重后才讨论。
6. 记录复核队列的人工耗时和正确率，否则不能声称记忆库降低了总成本。

python research\vehicle_memory\prototype.py
